# Security policy

Report a potential vulnerability or sensitive privacy concern privately. Do
not put exploit details, session text, account information, store contents, or
full exports in a public issue.

GitHub private vulnerability reporting was enabled and verified on 2026-09-07.
Use [Report a vulnerability](https://github.com/francarraras/flowmo-dev/security/advisories/new)
for confidential reports. On other copies or forks, use the security tab only
if that reporting option is available; this file does not enable the setting. See [GitHub's private-reporting instructions](https://docs.github.com/en/code-security/how-tos/report-and-fix-vulnerabilities/report-privately).

If private reporting is unavailable, testers should contact Fran Carrara through
the existing private channel used to receive their build. If you have no such
channel, open an issue asking only for a confidential security contact; include
no vulnerability details. Ordinary non-sensitive bugs belong in the repository's
[bug-report form](https://github.com/francarraras/flowmo-dev/issues/new?template=bug-report.yml).

Please include the affected revision, reproduction steps, impact, and any safe
mitigation you found. Attach a redacted diagnostic report when it is relevant;
never attach a full data export unless the owner explicitly requests it through
a private channel.

No public security email is configured. The maintainer should monitor GitHub
private reports and verify that this channel stays available for future releases.
There is no promised response deadline or separate security-support window yet.
