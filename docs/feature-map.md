# Flowmo feature map

This is the agent routing index for the current repository. It answers **what
feature is this, where is its behavior defined, which code owns it, and what
would prove it works**. It is not a product specification. If this map differs
from [`AGENTS.md`](../AGENTS.md), [`CONTEXT.md`](../CONTEXT.md), [`PROJECT.md`](PROJECT.md),
[`architecture.md`](architecture.md), or a linked surface document, those
sources win within their documented scope.

Presence here does not mean a feature is committed, distributed, useful, or
verified. Start every task with `git status --short` and inspect the relevant
diff. A passing test is automated evidence; it is not a substitute for driving
the real user surface.

## How agents use the map

1. Choose one feature ID. Do not widen the task until that feature has a
   checkable outcome.
2. Read its behavior source before reading implementation.
3. Trace from the user surface through its controller to Core or Sync. Do not
   edit `world.json` or `evidence.json` directly.
4. Reproduce with synthetic text in a disposable `FLOWMO_HOME` or simulator.
   Never inspect or drive the owner's normal store.
5. Run the named automated proof, then exercise the named real-user path.
6. Report untested entry points and proof gaps explicitly. Do not call a feature
   verified through a different path.

For phase-by-phase work, pick one feature row and follow it left to right:
behavior → owner → automated evidence → real-user proof.

## Known proof gaps

- There is no general Mac UI automation proving phase rendering, Classic/Mini,
  Reduce Motion, close/reopen, status-item clicks, notifications, or exporter UI.
- Focus Guard tests do not prove live macOS foreground and activation policy.
- Work Handoff tests prove target ownership and controller ordering, not live
  `NSWorkspace` activation policy.
- Sync tests prove reconciliation and persistence, not a real two-device
  CloudKit round trip.
- Flowmo Local tests and simulator builds do not prove free Personal Team signing, installation/profile renewal, or notification delivery on a physical iPhone.
- The Home Screen widget has no dedicated unit or UI test target.
- Live Activity projection/client tests do not prove native ActivityKit display, system placement, force-quit cleanup timing, or lifetime limits; these require separate device checks.
- Terminal PTY tests cover exits, signals, and restoration; visual redraw cadence still needs a live terminal check.
- Tutorial state and phone notification plans have deterministic tests; these do not prove native permission prompts, notification delivery, VoiceOver, or large-text layout.

These gaps are work to verify or deliberately leave manual. They are not
permission to claim the feature works because adjacent unit tests are green.
