# Flowmo roadmap

The shipped loop stays in [`PROJECT.md`](PROJECT.md). This file lists later product work. It does not change current behavior.

## Current state

Shipped:

- Mac window, compact visual rules, pin, mute, and phase cues
- Focus Guard
- menu-bar clock
- `flowmo live`, CLI verbs, and `status --json`
- local iPhone app
- iPhone Home Screen widget
- WP2 Mac local instrumentation foundation and explicit aggregate export
- WP3 exact-process resumption with automated proof and optional field audit

Mac and iPhone still use separate local files. Both have the shipped local history list. There is no cloud sync, Watch app, Live Activity, or theme system.

## Order

### 1. Evidence-bounded loop refinement

Before expanding surfaces, test the current loop one mechanism at a time. Keep
evidence local, aggregate, redacted, and explicitly exported; do not add a
network analytics SDK or store intention, Capture, Reflection, app identity, or
precise app-use timelines.

**WP2 instrumentation foundation — shipped.** The Mac app has a separate local
`evidence.json` with schema-safe, bounded aggregate counters and explicit
export/deletion. Its original six operational paths are: prompt offered after
confirmed hide, Stay focused chosen, Open once chosen, activation accepted,
activation not accepted, and interception failed before a prompt. Correlated
Open counts are recorded atomically and writes are ordered off the product
actor. It contains no typed text, session ID, app identity, PID, bundle ID,
path, raw duration, or event timestamp. Collection is best-effort, completeness
is unknown, and raw counts are not valid rates. The 16-write admission bound
and counter cap mean
they are only possibly saturated lower bounds on recorded paths, not estimates
of actual event volume. A valid delta requires chronological predeclared exports
from the same store and plan, no intervening reset, nondecreasing counters, and
no saturated counter used as exact. WP2 cannot establish learning, productivity,
well-being, or causal product benefit. Any eligibility, emission-timing, signal-
meaning, atomic-mapping, recorder admission/drop-policy, or cap change must mint
a new plan identifier before collection; never merge counts across plans.

**WP3 implementation — shipped with automated engineering proof.** After
**Stay focused**, Flowmo attempts to reactivate the exact prior unguarded app
instance using transient PID + bundle ID + launch identity. This does not
restore a document/window or prove return to a cognitive work context.

- Eligibility requires a committed Stay focused choice and a still-resolvable
  prior process identity.
- Success requires a matching activation notification within the frozen
  one-second timeout; API acceptance alone is insufficient.
- Missing identity, mismatch, rejection, or timeout must preserve today's safe
  behavior and grant no exception.
- Any identity mismatch or unsafe fallback rolls treatment back immediately.
- The automated acceptance proof runs 60 full component cycles through Guard,
  typed evidence, the real local aggregate store, chronological export, and the
  fixed evaluator. It requires 60 confirmations, zero failures, and zero
  recorder drops, and completes as part of the test suite rather than over a
  calendar month.
- A real-app success and safe fallback remain release smoke checks because the
  deterministic proof cannot establish macOS foreground behavior.

The `focus_guard_resumption_v1` counters obey the WP2 privacy contract and
remain aggregate-only. The pre-WP3 plan is not merged into it. The 60-attempt,
30-day evaluator remains available as an optional field audit; 30 days is its
maximum window, not a required wait or roadmap blocker. Raw unsupervised counts
cannot pass that audit. A focus or productivity claim would still require a
comparator and a relevant user outcome and harm measure.

Order after WP3 implementation:

1. Break framing and control: implemented with a neutral **Break** caption and a
   self-chosen **Continue** action. The proportional countdown remains a
   recommendation; the formula is unchanged and no recovery benefit is claimed.
2. Prime initiation: implemented as an up-to-two-minute voluntary settling beat
   with an explicit **Focus now** action. The timing and CLI contract are
   unchanged; no initiation benefit is claimed.
3. Reflection specificity: implemented as **What did you do, and what comes
   next?** The prompt combines concrete retrieval with a resumption cue; no
   memory, learning, or productivity improvement is claimed.
4. Ratio adjustment: frozen. Existing valid profile ratios are preserved, while
   new/reset profiles use 5. Completion no longer changes the ratio or appends a
   rolling duration sample because session length is not recovery evidence.

Before implementation, every experiment freezes: construct and operational
definition; eligibility and denominator; comparator and assignment; observation
window; missingness rule; primary benefit and harm; smallest worthwhile change
and maximum tolerable harm; planned sample or feasibility stop; rollback rule;
and analysis with uncertainty. Longer Focus and fewer bypasses are not
sufficient success measures.

### 2. One session across Mac and iPhone

Use an Apple-supported private sync mechanism only after its signing, conflict, offline, and recovery behavior is proven.

Required behavior:

- one canonical live session
- no silent merge of two Focus sessions
- timestamps remain the clock
- opening a remote session does not recovery-pause it
- local operation remains available when sync is unavailable

Do not add a Flowmo server or account dashboard to work around Apple platform limits.

### 3. Visual options

The current black and cyan frame remains the default. Any future visual options must not create a second product, add a dashboard, or put progress on Focus.

## Later

Watch, Live Activities, domain-specific learning protocols, and donation or
distribution work stay behind the items above. No commercial milestone is
required to justify a useful local product.

## Do not change

- Focus counts up until the user stops.
- No Pause control during Focus.
- Focus has no 0–100% ring.
- The Mac window remains the main Mac product.
- The CLI, menu bar, terminal, and widget remain supporting views.
- Do not resurrect screens or architecture from `~/Flowmo`.
